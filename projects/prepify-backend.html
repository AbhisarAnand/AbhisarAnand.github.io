Prepify interview analysis backend

Keeping analysis work out of the request cycle

  • Python
  • FastAPI
  • PostgreSQL
  • Celery
  • RabbitMQ
  • AWS S3
See the workflow ↓

The problem

Analysis without blocking the request

An interview analysis request can involve several stages of audio and video processing. Doing that work inside a single web request would make the user wait for the entire pipeline before receiving a response.

My contribution

I built FastAPI endpoints that create PostgreSQL job records, queue interview analysis through Celery and RabbitMQ, and return HTTP 202 with a job ID. I also wrote automated tests and technical documentation for the backend.

From input to outcome

How it works

The worker retrieves interview video from AWS S3, retries unavailable downloads up to 12 times, and falls back to audio-only analysis when needed. Job state, results and errors are stored in PostgreSQL; worker logs help trace failures while the application polls for progress.

  1. 01

    Accept the request

    An API call creates a persistent job record and returns HTTP 202 with a job ID. The client can start checking progress immediately.

  2. 02

    Queue the work

    Celery and RabbitMQ move the longer-running interview analysis into a worker, outside the web request.

  3. 03

    Retrieve and analyze

    The worker retrieves media, processes audio and video, and records the resulting analysis. S3 downloads include retries and an audio-only fallback.

  4. 04

    Expose the result

    PostgreSQL stores job state, results and errors. The status endpoint lets the client retrieve progress and completed output.

Behind the implementation

Design decisions

Give every request a durable identity

A stored job ID connects the original request to its status and result even though the worker has a different lifecycle from the API request.

Make missing media manageable

The worker retries unavailable video rather than failing at the first download attempt. If video remains unavailable, audio-only processing provides a defined fallback. I added tests, documentation and failure logs to make the workflow easier to maintain.

Project context

Prepify is a team project. This page focuses on my backend contribution. I have not published throughput or production reliability benchmarks.
