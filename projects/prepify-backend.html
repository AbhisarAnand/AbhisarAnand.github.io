Prepify interview analysis backend

Keeping analysis work out of the request cycle

The problem

An interview analysis request can involve several stages of audio and video processing. Doing that work inside a single web request would make the user wait for the entire pipeline before receiving a response.

My work

I built FastAPI endpoints that create PostgreSQL job records, queue interview analysis through Celery and RabbitMQ, and return HTTP 202 with a job ID. I also wrote automated tests and technical documentation for the backend.

How it works

The worker retrieves interview video from AWS S3, retries unavailable downloads up to 12 times, and falls back to audio-only analysis when needed. Job state, results and errors are stored in PostgreSQL; worker logs help trace failures while the application polls for progress.

Scope

Prepify is a team project. This page focuses on my backend contribution. I have not published throughput or production reliability benchmarks.
