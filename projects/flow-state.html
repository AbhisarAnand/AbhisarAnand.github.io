Dictation that fits into a macOS workflow

The problem

A complete desktop workflow

Dictation is useful only if the text ends up where you are working. Flow State brings speech recognition into the current application instead of making the user move between a recorder and an editor.

My contribution

I built the macOS application in Swift, using SwiftUI for the interface and AppKit for integration with the desktop. A global shortcut starts the workflow, WhisperKit handles local transcription, and the result can be inserted into the active application.

From input to outcome

How it works

The local code separates transcription behind a provider interface, allowing the application to select a backend without putting model-specific logic throughout the interface. Optional Groq formatting adapts the text to its destination.

  1. 01

    Start anywhere

    A global shortcut starts dictation while the user stays in the application they are working in.

  2. 02

    Transcribe locally

    WhisperKit converts the captured speech into text on the Mac, keeping transcription separate from the interface.

  3. 03

    Format when useful

    Optional Groq formatting adapts the transcript to the destination, such as an email, a message or code.

  4. 04

    Return to the task

    The result is inserted into the active application so the user does not need to move it out of a separate editor.

Behind the implementation

Design decisions

Fit the existing workflow

The desktop integration matters as much as the transcription model. I used AppKit for the global shortcut and application interaction, with SwiftUI for the interface.

Keep providers separate

A transcription provider interface keeps model-specific logic out of the rest of the app. Local transcription and optional cloud formatting remain separate choices.

Project context

WhisperKit handles transcription on the Mac. Optional Groq formatting sends the transcript to an external service; users can choose whether to enable it.
